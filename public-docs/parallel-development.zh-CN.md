# 运行并行任务 {#run-parallel-tasks}

使用原生客户端为多个编程 Agent 分配独立任务、审查改动并运行项目脚本。每个任务作为会话在现有目录中运行，同时查看对话、源码/Markdown、diff 和只读脚本日志。

开始之前，请准备好[桌面应用](/docs#desktop-app-recommended)、任务所需的现有本地目录，以及至少一个[已安装并完成认证的编程 Agent](/docs/supported-providers)。如果任务需要独立文件或分支，请自行准备不同的检出。现有 Git worktree 可以作为本地目录使用；Paseo 不创建或管理它们。

## 启动两个任务 {#start-two-tasks}

1. 打开 **New session** 并选择主机和现有目录。
2. 使用第一个任务的目录，例如 `/projects/list-filter`。
3. 选择 Agent 和模型，然后提交一个任务，例如：“为项目列表添加筛选功能。运行相关测试。”
4. 在另一个现有目录（例如 `/projects/settings-keyboard`）中新建会话。给它的 Agent 另一个任务：“为设置页面添加键盘导航。运行相关测试。”

两个 Agent 同时运行。在侧边栏的主机和目录下选择会话，查看进度和发送后续提示词。两个任务可使用相同或不同的 Provider。

不同的检出让文件修改相互独立。同一目录中的会话共享文件，并不隔离。如果想得到同一功能的两种实现，请使用不同的检出，给两个 Agent 相同的任务，比较结果后再选择一个。

## 审查每个改动 {#review-each-change}

选择一个会话，打开 **变更** 查看其目录的 diff。打开 **文件** 浏览和编辑源码。使用分栏，让 Agent 对话和你正在审查的代码并排显示。

把修改意见发送给该会话的 Agent。如果想听听别的意见，在同一目录中新建会话，让它在不编辑文件的前提下审查改动。同一目录中的会话共享文件。

## 运行并测试应用 {#run-and-test-the-app}

通过配置好的项目脚本运行项目测试/开发命令，或让 Agent 执行，再在 Paseo 查看只读输出。手动交互式 shell 操作可选择 **New session → Launch → Terminal**，在 daemon 主机上打开 shell，也可以使用自己的外部终端。

不同目录拥有各自的文件，但进程仍然共享机器的网络端口。请为每个正在运行的副本分配不同的开发服务器端口。通过[项目脚本和服务](/docs/worktrees#scripts-and-services)配置可重复运行的命令，并显式运行依赖安装等准备工作。

网页项目请在外部浏览器打开服务 URL，并确保浏览器所在机器能够访问；其他设备上的 localhost 不是 daemon 主机。

自动化浏览器检查使用项目另外安装的测试工具，或显式配置的外部 MCP 服务。Paseo 不内嵌浏览器，也不注入旧浏览器自动化工具。向外部工具提供具体步骤并审查真实结果，不要把未执行的测试计划当作成功。

## 选择要合并的内容 {#choose-what-to-merge}

审查每个目录的 diff 和实际测试结果。提交或创建 PR 前先提出剩余修改，可使用 Agent、原生 Git 操作或自己惯用的外部主机终端。

对于相互独立的任务，审查并合并每个分支。对于相互竞争的实现，选择你想保留的版本。不再需要某个会话时就把它归档。归档会保留目录和文件；保存好需要的工作后，请自行清理检出。

## 让 Agent 协调这些任务 {#let-an-agent-coordinate-the-tasks}

如果你想让 Agent 在现有目录中启动执行者并收集结果，请使用[编排](/docs/orchestration)。执行者会出现在 Paseo 中，你可以在它们工作时查看对话和改动。
